Ejercicio práctico de diagramas UML

Situación: diseñar el modelado de un sistema de préstamo de libros para una biblioteca. El objetivo es construir tres diagramas relacionados: casos de uso, clases y secuencia.

¿Qué deben realizar?

Una biblioteca necesita organizar el préstamo de libros. Los usuarios podrán buscar libros y solicitar préstamos. El bibliotecario podrá registrar libros y gestionar los préstamos. El sistema debe comprobar si el libro está disponible y registrar la fecha del préstamo y la fecha de devolución.

1

Analizar

Lean el caso, identifiquen quiénes participan y qué información necesita administrar la biblioteca.

2

Modelar

Construyan los tres diagramas en Lucidchart. Cada diagrama debe representar una parte del mismo sistema.

3

Revisar

Comprueben que los actores, las clases y los mensajes sean coherentes entre los tres diagramas.

Importante: no se requiere programar el sistema. La actividad consiste en representar visualmente cómo funcionaría y cómo estaría organizado.

Requisitos del sistema

  • Un usuario puede buscar un libro por título.
  • Un usuario puede solicitar el préstamo de un libro disponible.
  • El sistema registra el préstamo y las fechas correspondientes.
  • El bibliotecario puede registrar libros y consultar los préstamos.
  • Si un libro no está disponible, el sistema informa al usuario.

1. Actividad: diagrama de casos de uso

Representen las funciones que ofrece el sistema y los actores que las utilizan. Dibujen el límite del sistema como un rectángulo, los casos de uso como óvalos y conecten cada actor con las funciones que puede realizar.

Elementos que deben incluir

ElementoQué deben representar
Actor 1: UsuarioPersona que busca libros y solicita préstamos.
Actor 2: BibliotecarioPersona que registra libros y consulta o gestiona préstamos.
Casos de usoBuscar libro, solicitar préstamo, verificar disponibilidad, registrar libro y consultar préstamos.
Límite del sistemaUn rectángulo con el nombre “Sistema de préstamo de libros”.

Referencia visual simplificada

Usuario
Bibliotecario
Buscar libro

Verificar disponibilidad

Consultar préstamos

En Lucidchart, dibujen el rectángulo del sistema y coloquen dentro los óvalos. Los actores quedan fuera del límite y se conectan con las funciones correspondientes.

Pasos en Lucidchart

  1. Crear un documento nuevo y elegir una plantilla UML de casos de uso o usar formas básicas.
  2. Colocar los dos actores fuera del rectángulo del sistema.
  3. Agregar los cinco casos de uso dentro del rectángulo.
  4. Conectar cada actor con las funciones que utiliza.
  5. Guardar el diagrama con el nombre 01_Casos_de_Uso.

2. Actividad: diagrama de clases

Ahora representen la estructura del sistema. Una clase describe un tipo de objeto, sus atributos (datos) y sus métodos (acciones). Incluyan las clases sugeridas y conecten las que se relacionan.

Clases sugeridas

Usuario
− id: int
− nombre: string
− correo: string
+ buscarLibro()
+ solicitarPrestamo()
Libro
− isbn: string
− titulo: string
− disponible: boolean
+ consultarDisponibilidad()
+ actualizarEstado()
Prestamo
− id: int
− fechaPrestamo: date
− fechaDevolucion: date
− estado: string
+ registrar()
+ cerrarPrestamo()
Bibliotecario
− id: int
− nombre: string
+ registrarLibro()
+ consultarPrestamos()

Estas clases son una propuesta inicial. Dibujen las relaciones entre ellas y añadan multiplicidades si su docente las solicita.

Pasos en Lucidchart

  1. Crear un diagrama UML de clases.
  2. Para cada clase, crear un rectángulo dividido en nombre, atributos y métodos.
  3. Relacionar Usuario con Prestamo y Prestamo con Libro.
  4. Relacionar Bibliotecario con las tareas de gestión que realiza; pueden modelar esta relación según su criterio y justificarla.
  5. Guardar el diagrama con el nombre 02_Diagrama_de_Clases.
Para pensar: ¿por qué conviene que la información del préstamo esté en una clase propia y no únicamente dentro de Usuario o Libro?

3. Actividad: diagrama de secuencia

Representen, en orden temporal, qué sucede cuando un usuario solicita un préstamo. Incluyan las líneas de vida de Usuario, Interfaz, Sistema de biblioteca y Base de datos, y conecten los participantes con mensajes.

Secuencia que deben modelar

Usuario→Interfaz→Sistema→Base de datos
  1. El usuario selecciona un libro y solicita el préstamo.
  2. La interfaz envía la solicitud al sistema.
  3. El sistema consulta en la base de datos la disponibilidad del libro.
  4. La base de datos devuelve el estado del libro.
  5. Si está disponible: el sistema registra el préstamo, actualiza el estado del libro y envía una confirmación.
  6. Si no está disponible: el sistema informa que el libro no puede prestarse en ese momento.

Pasos en Lucidchart

  1. Crear un diagrama de secuencia UML.
  2. Colocar los cuatro participantes en la parte superior y trazar sus líneas de vida verticales.
  3. Agregar mensajes horizontales en el orden indicado.
  4. Usar mensajes de retorno para mostrar la respuesta de la base de datos o del sistema.
  5. Representar la decisión de disponibilidad con un fragmento combinado alt y dos condiciones: [disponible] y [no disponible].
  6. Guardar el diagrama con el nombre 03_Diagrama_de_Secuencia.

Entrega del trabajo

Al finalizar, cada equipo debe contar con los tres diagramas creados en Lucidchart y revisar que representen el mismo sistema de préstamo de libros.

Reflexión final

Respondan en equipo: ¿cómo se complementan los tres diagramas para explicar el mismo sistema?
